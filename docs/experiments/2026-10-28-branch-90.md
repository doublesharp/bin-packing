# Production branch coverage above 90%

Seven Terra Low batches and root integration added 28 focused Rust tests and
expanded existing cases. Production library code is unchanged. The added cases
exercise certificate validation, physical boundaries and bounded search behavior.

## Measurements

| Measurement | Covered branch outcomes | Branch coverage | Covered lines | Line coverage |

| Previous verified suite | 3,175 / 3,748 | 84.71% | 15,258 / 15,853 | 96.25% |

| Final verified suite | 3,393 / 3,748 | **90.53%** | 15,358 / 15,853 | **96.88%** |

This pass covers 218 additional branch outcomes and 100 additional source lines.
The denominator, compiler and counting scope match the previous measurement.
No production coverage exclusions were added. There are 355 uncovered outcomes;
the raw summary identifies their locations.

## Behavioral checks

- Independent 2D, staged, 3D and loading certificates: source identities, vector
  lengths, rotations, inventory, quantities, material totals and unsupported
  proof claims. Mutations start with valid certificates and check specific errors.
- Physical geometry: defect clearance, blade partitions, contact boundaries,
  each coordinate axis, circle/arc limits, legal upright rotations and delivery
  lanes in both directions.
- Input boundaries: dimension and quantity limits, stock/demand types, contours,
  holes, components, forecast sizes and inclusive search controls. Valid boundary
  counterparts accompany rejected cases.
- Repair search: independently enumerated allocation profiles, separate profile
  and check budgets, canonical stock eligibility, finite inventory, charged work
  and repeated-item grids with a vacancy.

The central run corrected a fixture type, unique stock labels, a Clippy type alias
and an unfinished repair incumbent. The corrected repair fixture explicitly
accounts for every unplaced item. No new library defect was established.

The earlier [controlled fault checks](2026-10-28-branch-proof.md) document three
deliberate mistakes caught by expanded tests. The current coverage percentage
measures exercised paths; it does not prove universal correctness or performance.

## Verification and scope

`CARGO_BUILD_JOBS=2 ./scripts/check-quality.sh` passes **630 Rust tests**,
**43 Python tests**, formatting, Taplo, typos, strict workspace Clippy and rustdoc.
One pre-existing optional Rust test remains ignored. The final instrumented run
also passes all 630 Rust tests and the requested 96% line / 90% branch floors.

Coverage uses the same pinned `nightly-2026-10-12` compiler and matching LLVM tools
as the preceding report. It counts unique production LCOV line and branch
records across all features and Rust test targets. Test-only items and external
test modules are excluded. JavaScript/browser coverage and doctests are outside
this percentage. Native/WASM implementation behavior was unchanged in this pass.

Comparison with the saved source verifies unchanged production code across 63
files after removing test-only items and ignoring empty lines. Source hashes are
unchanged during the final measurement. The [testing guide](../testing-confidence.md)
now recommends a 90% branch minimum for subsequent measurements.

Raw profiles, LCOV/LLVM exports, source snapshots, logs and verification receipts
are under `/Volumes/Scratch/bin-packing/reports/branch90-20261028/`. Disposable
task-owned build output was removed after ownership and open-process checks;
shared build caches remain.
